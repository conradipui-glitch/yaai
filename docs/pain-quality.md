# Pain Quality Gate — проверка качества Jev на ручной разметке

Этот блок измеряет **качество обнаружения проблем аудитории**, а не максимальную вероятность, выданную моделью. Оценка человека остаётся отдельно от Jev: ни одна метка не создаётся автоматически.

## Подготовить выборку из собранных данных

Сначала получите полный Pain Map обычным процессом из [pain-discovery.md](pain-discovery.md). Требуется обновлённый Pain Map с **evidenceLedger**, в котором сохраняются и принятые, и отвергнутые наблюдения: без отвергнутых примеров невозможно честно оценить пропущенные боли.

~~~bash
npm run pain:review -- \
  --map /private/pain-map.json \
  --sample-size 100 \
  --out /private/pain-review.json
~~~

Выборка объединяет разные типы источников (Wordstat/поисковые фрагменты) и решения модели (нашла/не нашла боль). Выборка детерминирована по ID, но **стратифицирована**, поэтому её доли нельзя без поправок переносить на весь интернет или всю аудиторию.

**Аннотация слепая**: файл показывает исходный запрос, фрагмент и ссылку, но не показывает ответ Jev. В записи для каждого наблюдения изначально:

~~~json
{
  "label": {
    "isPain": null,
    "category": null,
    "evidenceSupported": null,
    "reviewer": "",
    "notes": ""
  }
}
~~~

Для `isPain=true` укажите категорию из PAIN_CATEGORIES (см. lib/pain-discovery.mjs). `evidenceSupported=true` означает, что представленный текст достаточно подтверждает такую боль; рекламное обещание само по себе не является жалобой клиента. При `isPain=false` используйте `category=null` и `evidenceSupported=false`.

## Быстро разметить в терминале без правки JSON

~~~bash
npm run pain:review:interactive -- \
  --review /private/pain-review.json \
  --reviewer "analyst"
~~~

Программа выводит по одному источнику и спрашивает: есть ли проблема, какая категория, подтверждает ли это текст, нужна ли заметка. Клавиши: **д** — да, **н** — нет, **п** — пропустить, **в** — выйти. Каждая оценка сохраняется сразу. Повторный запуск продолжит незавершённую очередь.

Это локальная команда. Ключи Яндекса/OpenRouter не нужны, API не вызываются. Не загружайте материалы клиента в публичный репозиторий.

## Посчитать реальные метрики

~~~bash
npm run pain:quality -- \
  --map /private/pain-map.json \
  --review /private/pain-review.json \
  --out /private/pain-quality.json \
  --md /private/pain-quality.md \
  --target-labels 50
~~~

Результат — матрица ошибок (TP/FP/TN/FN), расхождения с человеком и четыре показателя:

- **Pain Precision = TP / (TP + FP)** — доля действительно подтверждённых болей среди положительных ответов модели.
- **Pain Recall = TP / (TP + FN)** — доля настоящих болей, найденных моделью **среди размеченных наблюдений**, включая отрицательные прогнозы.
- **Validated Evidence Coverage** — доля положительных ответов модели, для которых ревьюер подтвердил поддержку в исходном тексте.
- **Cost per Valid Pain** — суммарная цена Jev для размеченных наблюдений / количество верно найденных болей (USD). **Не включает Яндекс API и трудозатраты на разметку.**

Дополнительно считается точность категории среди верно найденных болей и разбивка ошибок по Wordstat и SERP.

Никаких искусственных 0% или 100% при отсутствии оценок: если знаменатель равен нулю или неизвестна стоимость, соответствующая метрика будет `null`. До минимальной разметки 50 записей и хотя бы пяти положительных/отрицательных человеческих примеров статус отчёта — **insufficient_manual_labels**. Даже после этого метрики остаются предварительными для размеченной выборки, а не обещанием качества на рынке.

## Проверка корректности

~~~bash
npm run pain:quality:selftest
npm run check
~~~

Selftest использует **только искусственные тестовые метки**, чтобы проверить формулы, отложенные записи, несовпадающие идентификаторы карт и отсутствие вымышленных процентов. Он **не** подтверждает качество Jev на настоящих человеческих оценках.

Первый реальный пилот: собрать 50–100 наблюдений по одной тематике, вручную разметить **включая отрицательные предсказания**, посмотреть FP/FN и поправить критерии Jev или источники, после чего повторить на независимой выборке.
