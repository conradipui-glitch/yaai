# Jev для SEO, рекламы и GEO: рабочие сценарии YA AI

Основа: [Ryze, Jev for SEO/GEO, 20.09.2026](https://www.get-ryze.ai/blog/jev-for-ads-and-seo-geo).
В статье предлагается цикл **источники → отбор кандидатов → решение Jev → проверка человеком → LLM, если нужен текст**. Это описание возможностей, не доказательство их точности: Ryze прямо указывает, что Jev ещё не запущен у них в production на дату публикации.

## Что внедрено

В YA AI используются уже существующие Jev Decisions API, типы Choice/Noul/Score и сохраняемые после каждого запроса чекпойнты. Появились три SEO-профиля со своими форматами входных данных и **только рекомендациями к ручной проверке**:

| Задача | Источник, который пользователь уже может подготовить |
| --- | --- |
| Search-term triage: покупатель или нецелевой запрос | Выгрузка поисковых фраз с необязательными измеренными кликами/конверсиями |
| Landing page match: соответствует ли страница запросу и обещанию | Запрос + URL + заголовок и фрагмент страницы |
| Cannibalization: конкурируют ли две страницы за одинаковое намерение | YA AI `webmaster:overlap` + заголовки и описания страниц |

**Ещё не внедрены из статьи:** разметка рекламных креативов (нужен источник Meta/Ads), карта внутренних ссылок (нужен инвентарь страниц), проверка тонких страниц (нужен полный контент), GEO-упоминания и конкуренты в ответах (нужны реальные датированные ответы моделей), создание страниц по конверсионным запросам (нужны отчёт продаж и актуальный список URL). Не будем выдумывать отсутствующие данные.

## 1. Поисковые фразы

`/private/terms.json`:

~~~json
{
  "businessOffer": "B2B CRM и обработка заявок",
  "terms": [
    {"id": "ads-001", "query": "автоматизация заявок цена", "campaign": "search",
     "clicks": 12, "conversions": 2, "revenue": 4000},
    {"id": "ads-002", "query": "что такое CRM", "campaign": "search"}
  ]
}
~~~

Незаполненные метрики остаются `null`, **не нулём**. Jev не вычисляет продажи из текста запроса.

## 2. Соответствие посадочной страницы

`/private/matches.json`:

~~~json
{
  "matches": [
    {"id": "landing-001", "query": "заказать кровлю под ключ",
     "adPromise": "Бесплатный замер",
     "url": "https://site.example/roof/",
     "pageTitle": "Кровельные работы",
     "pageExcerpt": "Выезжаем на замер, рассчитываем сметы и монтируем кровлю."}
  ]
}
~~~

Это проверка предоставленного фрагмента, а не автоматический обход живого сайта.

## 3. SEO-каннибализация

Сначала сформируйте текущим инструментом отчёт по разрешённой выгрузке Вебмастера:

~~~bash
npm run webmaster:overlap -- --input /private/webmaster.csv --out /private/overlaps.json
~~~

В результате `overlaps.json` уже есть поле `overlaps`. Добавьте к этому JSON массив `pageSnapshots`, содержащий URL, заголовок и краткое описание каждой интересующей страницы:

~~~json
{
  "overlaps": [
    {"query": "ремонт кровли", "totalImpressions": 125,
     "pages": [
       {"url": "/roof/", "impressions": 75, "clicks": 5, "averagePosition": 4.2},
       {"url": "/roof-repair/", "impressions": 45, "clicks": 4, "averagePosition": 5.1}
     ]}
  ],
  "pageSnapshots": [
    {"url": "/roof/", "title": "Кровля под ключ", "summary": "Новая кровля, замер и смета"},
    {"url": "/roof-repair/", "title": "Ремонт протечек", "summary": "Восстановление покрытия"}
  ]
}
~~~

YA AI рассматривает до трёх наиболее заметных URL на запрос и до трёх пар между ними. Пары без описаний исключаются с указанием причины. **Общий запрос ещё не доказывает опасную каннибализацию**.

## Запуск: подготовка → добровольная оплата → разбор

**Подготовка** без сети:

~~~bash
npm run jev:seo -- prepare \
  --task search-term-triage \
  --input /private/terms.json \
  --out /private/search-prepared.json \
  --limit 100
~~~

Вместо `search-term-triage` можно передать `landing-page-match` или `seo-cannibalization`. Получится файл с кандидатами, сохранённым контекстом, источником, пропусками и подписью профиля. Откройте его и оцените число платных вызовов.

**Оценка Jev**, только после явного разрешения и с сохранением чекпойнтов:

~~~bash
npm run jev:evaluate -- \
  --input /private/search-prepared.json \
  --profile examples/evaluation-profiles/search-term-triage.json \
  --out /private/search-jev.json \
  --execute
~~~

**Очередь ручной проверки**, офлайн:

~~~bash
npm run jev:seo -- route \
  --prepared /private/search-prepared.json \
  --evaluations /private/search-jev.json \
  --out /private/search-review-queue.json
~~~

Выходные приоритеты: `priority_review`, `uncertain_review`, `routine_review`. Это **только порядок рассмотрения**, а не автоматическое принятие решений. YA AI перепроверяет ID, хеши исходного состояния, точные вопросы и пороги профиля. Готовые файлы не перезаписываются.

**Ничего не публикуется**, запросы не добавляются в минус-слова, страницы не объединяются и рекламные бюджеты не меняются. Содержимое сайтов и показания аналитики считаются пользовательскими снимками данных, не подтверждёнными YA AI самостоятельно.

Ограничения: пороги уверенности не откалиброваны человеческой разметкой для этих трёх задач; цены и доступность Jev могут измениться. Отчёт содержит реальные расходы, возвращённые API, а неизвестная стоимость остаётся неизвестной. Не публикуйте данные клиентов в открытом репозитории. Тесты `npm run check` полностью офлайн.
