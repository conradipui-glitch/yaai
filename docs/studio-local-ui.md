# YAAI Studio — локальный интерфейс и карта Pain Discovery (2026-10-16)

Studio работает **на уже существующем локальном сервере**, рядом с Wordstat.

~~~bash
npm start -- --workspace /private/yaai-workspace
~~~

Открыть: **http://127.0.0.1:8787/studio.html**. Wordstat и Knowledge Layer
остаются доступными по адресу http://127.0.0.1:8787/.

## Что действительно реализовано

- Светлая адаптивная Studio на русском с тёмной темой.
- Обзор реальных проектов и сохранённых заданий.
- Безопасные read-only API
  - \`GET /api/studio/overview[?case=<id>]\` — список проектов / задачи выбранного проекта;
  - \`GET /api/studio/pain-report?case=<id>\` — **один** сохранённый Evidence Report v1 в проекте;
  - \`GET /api/config\` — наличие локальной Wordstat-конфигурации и счётчик попыток текущего серверного процесса.
- Из настоящего Evidence Report v1: гипотезы на майндмэпе, связанная таблица,
  карточка выбранной категории, отдельные наблюдения с исходными URL (если они есть),
  число фрагментов выдачи и Wordstat-фраз, отметки о необходимости проверки.
- Переходы в действующий Wordstat и документацию MCP/CLI/Jev.

## Как подключить **сохранённый** отчёт Pain Discovery

Требуется **структурированный JSON Evidence Report v1**, созданный
\`npm run report:pain\`, а **не** исходная карта \`pain-map.json\` и не HTML-страница.

Выберите идентификатор проекта (case ID), например \`example-seo\`.
В приватной рабочей папке разместите файл строго по пути:

~~~text
<workspace>/results/<case-id>/pain-report.json
~~~

Это осознанное правило: URL веб-страницы не может запросить произвольный
локальный путь, и отчёт другого проекта не подхватится по имени случайно.

**Вариант 1.** Уже есть созданный \`report.json\`. Скопируйте его в
\`results/<case-id>/pain-report.json\` выбранного проекта. Не перемещайте
и не перезаписывайте исходный отчёт. В Windows создайте вложенную папку
обычным Проводником, затем скопируйте файл.

**Вариант 2.** Есть только старый \`pain-map.json\`. Получите Evidence Report
офлайн, направив результат сразу в выбранную папку:

~~~bash
npm run report:pain -- \
  --map /private/previous/pain-map.json \
  --html /private/yaai-workspace/results/example-seo/pain-report.html \
  --json /private/yaai-workspace/results/example-seo/pain-report.json
~~~

CLI не перезаписывает существующие результаты: если файл уже есть,
используйте новое имя для архива и явно заменяйте подключаемый
\`pain-report.json\` **только после ручной проверки**, сохраняя копию прежнего.

Затем обновите Studio (кнопка ↻), выберите проект, откройте
«Проблемы клиентов» и нажмите категорию в карте/таблице.
Поисковая фраза без URL — отдельный тип свидетельства, ссылка
на неё не придумывается. Фрагменты SERP содержат исходные веб-URL,
но ни система, ни отчёт **не подтверждают полный контекст страницы**.

Если отчёта нет, карта честно показывает инструкцию и пустое состояние;
если отчёт повреждён/не подходит под версию — выдаётся ошибка без
автоматического исправления, подмены числа записей или попытки
оплачиваемого повторного исследования.

## Границы и безопасность

- Only loopback \`127.0.0.1\`; существующие проверки Host/Origin.
- Не производится запись задач/артефактов, сетевые запросы к
  поисковикам, вызовы ИИ или списание API-квот.
- Путь фиксирован: \`results/<case-id>/pain-report.json\`. Обязательны
  реальный файл и папка; символические ссылки и попытки обхода пути
  отвергаются. Максимальный объём отчёта — 8 МиБ.
- Сервер валидирует версию отчёта, уникальные ID, связь
  claim → accepted observation, счётчики и безопасность URL.
  Он отдаёт браузеру только нужные поля, не исходный документ целиком
  и не файловые пути / ключи. Веб-интерфейс вставляет тексты через
  \`textContent\`, а внешние ссылки открываются отдельно с \`noopener noreferrer\`.
- Все категории \`hypothesis_requires_validation\`, **даже когда
  Jev относит свидетельство к категории**. «Принято моделью» не равно
  жалобе, людям, подтверждённой рыночной потребности или причинной связи.
  Частотности Wordstat пересекаются и не суммируются.
- Реальное качество исследования требует независимой человеческой
  разметки. Статус \`provisional_human_benchmark\` относится только
  к размеченной выборке.
- Данные могут быть конфиденциальными: храните рабочую папку приватно,
  не публикуйте её в GitHub и не выставляйте этот сервер в интернет.

## Чего пока нет

Studio не создаёт отчёты, не запускает поисковые/платные исследования
через карту, не хранит API-ключи и не даёт полноценный чат агента.
Удалённый VPS, Telegram и модельный роутинг не заявляются готовыми.

## Техническая проверка

~~~bash
node scripts/studio-selftest.mjs
node scripts/studio-pain-selftest.mjs
node scripts/server-http-selftest.mjs
npm run check
~~~

В тестах используется **искусственный отчёт**, сформированный
тем же production \`buildPainReportDocument()\`, с хорошими и намеренно
повреждёнными данными. Проверяются изоляция кейсов, отсутствие выдуманных
цитат и метрик, безопасные URL, некорректные IDs/счётчики, симлинки,
локальный HTTP и нулевые платные обращения. Тесты не заменяют ручную
проверку реального клиентского отчёта в браузере.
