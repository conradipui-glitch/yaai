# YAAI Studio — первый живой локальный интерфейс (2026-10-16)

## Открыть

Запустите **обычный локальный сервер** из уже установленного репозитория:

\`\`\`bash
npm start -- --workspace /path/to/private/yaai-workspace
\`\`\`

Откройте **http://127.0.0.1:8787/studio.html**. Классический инструмент
Wordstat остаётся доступным по адресу http://127.0.0.1:8787/.
В нём теперь есть ссылка на Studio.

Studio — **не отдельный сервер** и **не публичный SaaS**. Работают
существующие локальные Host/Origin проверки и bind 127.0.0.1.
Условия защищённого VPS-развёртывания из общего плана не изменились.

## Что уже реально работает

- Светлая русскоязычная адаптивная оболочка; пользователь может включить
  тёмный режим, переключаться по разделам и обновлять данные.
- GET \`/api/studio/overview\` — ограниченный список локальных проектов
  с идентификатором/названием. Никаких case JSON, путей к файлам,
  токенов, ключей или исходных свидетельств.
- GET \`/api/studio/overview?case=<id>\` — список **уже сохранённых** задач
  выбранного проекта с действительными статусами. Данные получаются из
  \`lib/task-executor.mjs\`, с существующей валидацией и ограничениями;
  чужие проекты не смешиваются в ответе.
- GET \`/api/config\` — состояние **наличия** Wordstat-конфигурации и
  числа API-обращений в **текущем процессе сервера**. Это не проверка
  провайдера и не финансовая отчётность.
- Ссылки на действующий Wordstat UI и актуальные инструкции MCP/Jev/Pain.

## Чего здесь ещё нет

- Mindmap в разделе «Проблемы клиентов» — **наглядный шаблон** категорий,
  не результат кластеризации. Никаких синтетических цитат, сомнительных
  «67% подтверждённых гипотез» и фальшивых метрик.
- Импорт конкретного сохранённого Pain Discovery JSON/HTML и привязка
  evidence → cluster → claim ещё не реализованы. Подключать отдельным
  шагом после проверки схемы реального результата и допустимого доступа.
- Чат YAAI, маршрутизация моделей, удалённые агенты, долговременный
  ключевой сейф и управление API из браузера **не реализованы**.
  MCP/CLI работают в существующих пределах.
- Studio не запускает Wordstat/API, не создаёт задач и не производит
  оплачиваемых или внешних операций.

## Тесты

\`\`\`bash
node scripts/studio-selftest.mjs
node scripts/server-http-selftest.mjs
npm run check
\`\`\`

Проверяются безопасный доступ к кейсам, изоляция выбранного проекта,
неподмена статусов, отсутствие секретов в проекции, честные пустые
состояния, загрузка HTML и endpoint с учётом локального HTTP guard.

**Следующий небольшой этап:** read-only импорт **одного** существующего
проверенного Pain Discovery отчёта из папки текущего проекта и
визуализация **его** реальных групп/цитат/ссылок на источники.
Никаких живых платных источников или архитектуры SaaS для этого шага.
